# 同类项目深度调研（2026-11-07）

调研方法：逐个通读项目 README、架构说明与设计文档，不只看首页简介。目的：提炼可融合进
World Games 的设计点，对照本项目定位（AI 负责叙事、引擎负责规则结算与状态单点写入）。

## 一、MCP 游戏后端类

### 1. mnehmos.rpg.mcp — Agentic Embodied Simulation Kernel
- 定位：规则强制 RPG 后端，"让 LLM 当一个不能作弊的 GM"。
- 亮点：
  - **工具收敛**：195 个工具收敛为 28 个（action enum + 模糊匹配 + 引导式报错）。
    工具过多会稀释模型注意力、放大误调用率；用 `action` 参数 + typo 容错 + 建议式
    错误信息替代工具爆炸。
  - D&D 5e 战斗（先攻/AC/死亡豁免）、法术位追踪、NPC 跨会话记忆。
- 对本项目的启示：WG 有 67 工具，数量健康但可评估是否对高频操作提供 action-enum 聚合
  门面；报错信息已做引导式的可对照 `verify_mechanics.py`。暂不收敛（AGENTS.md 已锁定
  工具数与文档一致性），可列为远期选项。

### 2. text-adventure-handler-mcp（narrowstacks）
- 亮点：
  - **批量执行工具** `execute_batch`：单回合内一次调用完成多个游戏动作，降低往返延迟。
  - **叙述者内心独白工具** `narrator_thought`：给 GM 一个"私人草稿区"做情节规划，不进玩家可见文本。
  - SQLite 持久化 + 动态属性（每个冒险自定义属性集）+ 阵营/状态效果/昼夜。
- 对本项目的启示：批量动作与"GM 私有规划区"是真实缺口。WG 的 `inbox` 侧写 + 建议
  剪枝已覆盖部分；`narrator_thought` 类似物可用台账 `notes`（私有字段）承接——已有
  雏形，可在文档中显式引导。

### 3. mcp-state-of-play（cgast）
- 亮点：FastMCP + **stdio 与 streamable-http 双传输**；Docker 一键起；web 仪表盘轮询刷新。
- 对本项目的启示：WG MCP 目前 stdio 单传输。`mcp` 1.x/2.x 兼容层已具备加 http 传输的
  条件，属于低成本高价值缺口（远程 agent 接入场景）。

### 4. role-playing-mcp-server（fritzprix）
- 亮点：
  - **Delta 系统**：嵌套字段路径更新（`characters[0].level`）+ 变更实时可视。
  - **Game Over 流**：isGameOver → 共情式结束画面（解释"如果当初…"）→ 一键重开并保留
    上一局摘要作为新局上下文。
- 对本项目的启示：WG 重放日志已是 delta 的超集（seq+指纹链）；"局终摘要 → 带上下文
  重开"是可低成本落地的体验点（sessions 已有存档库）。

### 5. dungeon-mcp-server（compose-and-dragons）
- 亮点：YAML 定义世界 + **ASCII 地图工具** `display_dungeon_map`，给无图形环境提供空间上下文。
- 对本项目的启示：WG 的 panel.js 已有事业线图；可为 CLI/MCP 场景补一个纯文本小地图
  渲染（低成本）。

## 二、LLM 前端 / 状态追踪类

### 6. SillyTavern（生态位参照）
- 300+ 贡献者、扩展体系（角色卡/世界信息/RAG/群聊）。对 WG 的意义：WG 的设定包
  （rules 字段）≈ 其"世界信息+角色卡"的确定性替代，差异化叙事点应写进 README：
  "model remembers nothing, the engine remembers everything"（源自 StatefulLore 的表述）。

### 7. StatSuite / Stat Tracker（SillyTavern 扩展）
- 亮点：**用独立小模型做状态追踪**，不占主模型上下文、不受采样随机性影响；状态块只注入
  最新一份 @depth 1。
- 启示：印证 WG "状态由引擎单点写入、LLM 不记账"的架构正确性；README 可引用该痛点
  作为问题陈述。

### 8. StatefulLore（SillyTavern 扩展）
- 核心哲学：**"The model is a writer, not a database"**——模块每回合构建权威状态快照注入
  prompt，模型只读场景只管写作。
- 亮点：HUD 浮出面板（角色卡/背包/任务）、lore 模块用 JS 实现 `processTurn()`/
  `handleResponse()`、GitHub 自动更新版本探测。
- 启示：WG 的台账预算打包正是该思想的实现；HUD 概念与 panel 已有图层对应。"模型是
  写手不是数据库"一句话值得进 README 英文首屏。

### 9. AetherState（本地代理型追踪器）
- 亮点：**fail-open**——自身出错时不阻断原始对话；**安全重试**——提交过的伤害/物品
  变更不因重试而重复（幂等）。
- 启示：WG 动作日志的 seq 链天然幂等；fail-open 原则适用于 panel/serve 后端——局部
  断言失败不能让整页崩溃（可在 `panel.py` 错误处理路径复核）。

## 三、叙事脚本语言 / 混合引擎类

### 10. Waidrin（p-e-w）
- 亮点：全类型化状态机 + **基于 JSON Schema 的受限生成**动态创建角色/地点；结构化叙事
  事件（非纯聊天）；上下文压缩；插件系统；AGPL。
- 启示：受限生成依赖模型侧支持，WG 不控制模型侧，但"结构化事件而非聊天消息"与 WG
  的动作日志同构，确认方向。

### 11. llmrpg-core
- 亮点：monorepo 分包（core/sandbox/llm-integration）、worldbook 事件条件化确定性可重放。
- 启示：WG 的 settings bundle + 事件表等价；无新增缺口。

### 12. DungeonMaster（LangGraph 示例项目）
- 亮点：GM 节点与规则引擎节点分离、human-in-the-loop 中断点、工具调用掷骰。
- 启示：与 WG "AI 叙事 / 引擎结算"分工一致；无新增缺口。

### 13. ink（inkle）/ Yarn Spinner / Twine / Ren'Py / WebGAL / Dialogic
- ink：叙事内容与叙事逻辑统一语言，AI 友好度最高，JSON 导出可接任何后端。
- Yarn Spinner：剧本式纯文本；明确"不含生成式 AI 是设计决定"。
- 启示：WG 的设定包 schema 是 JSON，天然可被 AI 生成/校验（settings_loader 纯标准库
  校验已落地）。可在 README 强调"AI can author the bundle, engine validates it"。

## 四、结论：确认的缺口（按性价比排序）

| # | 缺口 | 来源项目 | 落地方式 | 成本 |
|---|------|----------|----------|------|
| 1 | MCP streamable-http 传输 | state-of-play | mcp_server 增加可选 `--http` 模式 | 低 |
| 2 | "模型是写手不是数据库"定位语 + 问题陈述 | StatefulLore/StatSuite | README 首屏改写 | 低 |
| 3 | 局终摘要→带上下文重开 | role-playing-mcp | sessions + 摘要字段引导 | 中 |
| 4 | 纯文本小地图 | dungeon-mcp | CLI/MCP 渲染地点邻接 | 中 |
| 5 | GM 私有规划区显式引导 | text-adventure-handler | 文档/工具描述标注台账 notes 私有语义 | 低 |
| 6 | fail-open 复核 | AetherState | panel.py 错误路径审查 | 低 |

不采纳并说明理由：
- 工具收敛到 28：会破坏文档一致性门禁与既有生态；WG 工具粒度已按域划分且 67 个可控。
- 引入 LangGraph/Redis/Docker：违反零依赖硬约束；WG 的 JSON 状态文件 + 单点写入更符合
  "可审计、可重放"定位。
- 受限生成（JSON Schema decoding）：需要模型推理侧支持，超出 WG 规则层职责边界。
